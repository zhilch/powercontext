# 忘川客栈 · 运行说明

> 作品：**忘川客栈**——一个"记忆是一种资源"的互动剧情小游戏。
> 技术：**Dify**（流程编排）+ **PowerContext**（记忆账本）。
> 提交物：本目录下的 DSL、说明、验证样例与初始化脚本。

## 一、作品创意与玩法

客栈的规矩：客人喝下忘川水，睡一觉就会忘掉一切。世上只有掌柜**阿箬**那本《记忆账本》能留下东西。

- 你说 **「记住：我叫沈砚，怕水。」** → 阿箬提笔在账本上记一行，并把这句话复述给你。
- 你说别的（「掌柜的，来壶酒」）→ 阿箬**先翻账本**再开口：账本里有的，她主动提起；账本里没有的，她真的不知道，会露出陌生的神色。
- **换一个新会话**（甚至关掉应用再打开）→ 阿箬依然记得沈砚和"怕水"。这不是会话记忆，是 PowerContext 里的长期记忆。
- 如果账本里查不到任何相关记忆，她会按初次见面来演，而不是编造你上次说过什么。

为什么好玩：记忆不是外挂，而是**玩法本身**——你得决定留下什么、怎么留，才能让下一次见面的阿箬"认识"你。

## 二、技术分工

| 组成 | 在作品中的作用 | 对应位置 |
| --- | --- | --- |
| **Dify** | 承担全部流程编排：输入判断、HTTP 调用、数据整理、模型生成、回答输出 | `忘川客栈.yml` 的 9 个节点 |
| **PowerContext** | 记忆账本：保存玩家要求记住的事，并在每次开口前按当前这句输入检索相关记忆 | `http_remember`、`http_search` 两个 HTTP 节点；`scripts/init_powercontext.sh` 初始化 |

工作流结构：

```
玩家输入
  ├─ 含「记住」→ code 取出去掉前缀的那句话 → POST /v1/memory/remember → 记账回执
  └─ 其他      → POST /v1/memory/search   → code 整理账本 → LLM(阿箬，人设+账本) → 回答
```

两个 HTTP 节点直接调用 PowerContext 的公开 HTTP API（`/v1/memory/remember`、`/v1/memory/search`），
不依赖任何自定义插件；Dify 侧只用到官方的 HTTP Request、Code、LLM、Answer、IF/ELSE 节点。

> 说明：本题要求"seekdb 或 PowerContext 至少一种"，本作品使用 **PowerContext**。
> 部署脚本里 Dify 的向量库后端配置为 seekdb（`VECTOR_STORE=seekdb`），但那只是让 Dify 能起来，
> **本作品没有知识库**，seekdb 不承担作品的数据职责，也不作为技术结合的依据。

## 三、运行环境

| 项目 | 版本/要求 |
| --- | --- |
| Dify | 1.18.0（源码 `docker/docker-compose.yaml` 部署） |
| PowerContext | 1.2.0（镜像内 `pip install "powercontext[cli,server]==1.2.0"`） |
| 数据库 | Dify：PostgreSQL 15（容器内置）；PowerContext：SQLite（命名卷持久化） |
| 向量库 | seekdb（`oceanbase/seekdb:latest`，Dify 部署依赖） |
| 模型 | 任一 OpenAI 兼容接口的对话模型（见第五节） |
| 资源 | 内存 ≥ 8 GB、磁盘 ≥ 15 GB（镜像约 6 GB） |
| 系统 | Linux + Docker 24+ 与 Docker Compose v2（本文在 WSL2 Ubuntu 24.04 实测） |

## 四、部署步骤

### 1. 启动 Dify

```bash
# 取官方 1.18.0 源码（或使用你已有的 dify/docker 目录）
curl -fsSL -o dify.tar.gz https://codeload.github.com/langgenius/dify/tar.gz/refs/tags/1.18.0
tar -xzf dify.tar.gz && cd dify-1.18.0/docker
cp .env.example .env

# 关掉 weaviate（其镜像源 cr.weaviate.io 在部分网络不可达），改用 seekdb
sed -i 's/^VECTOR_STORE=.*/VECTOR_STORE=seekdb/' .env
cat >> .env <<'EOF'
OCEANBASE_VECTOR_HOST=seekdb
OCEANBASE_VECTOR_PORT=2881
OCEANBASE_VECTOR_USER=root
OCEANBASE_VECTOR_PASSWORD=difyai123456
OCEANBASE_VECTOR_DATABASE=dify
EOF

# 填入随机 SECRET_KEY / INIT_PASSWORD 后启动
docker compose up -d
```

首次访问 <http://localhost> 用 `.env` 里的 `INIT_PASSWORD` 设置管理员账号（邮箱 + 密码）。

### 2. 启动 PowerContext 记忆服务

```bash
cd dify/powercontext
docker compose -f docker-compose.powercontext.yaml up -d --build
curl -fsS http://127.0.0.1:8000/health/live   # 期望 200
```

该 compose 把 PowerContext 接入 Dify 的 `docker_default` 网络，容器名 `powercontext`，
因此 Dify 工作流里用 `http://powercontext:8000` 访问；数据落在命名卷 `powercontext-data`。

### 3. 初始化记忆账本

```bash
cd dify/scripts
bash init_powercontext.sh
# 最后一行输出：初始化完成。WANGCHUAN_SCOPE_ID=<scope_id>
```

脚本会建 scope（幂等键 `wangchuan-inn-main`）并写入 3 条开局设定（客栈规矩、阿箬人设、失忆规则）。

### 4. 导入 DSL

1. Dify → 工作室 → 导入 DSL 文件 → 选择 `dify/忘川客栈.yml`。
2. 打开应用 → **环境变量**，把 `WANGCHUAN_SCOPE_ID` 改成第 3 步输出的 `scope_id`
   （`POWERCONTEXT_BASE_URL` 默认 `http://powercontext:8000`，若 PowerContext 不在同网络改成实际地址）。
3. 打开 LLM 节点「阿箬开口」，把模型换成你工作区里已配置的对话模型（见下节）。
4. 发布应用。

### 5. 配置模型（OpenAI 兼容接口）

设置 → 模型供应商 → **OpenAI-API-compatible**：

| 字段 | 填法 |
| --- | --- |
| API Key | 你的 key |
| API endpoint URL | 例如 `https://api.deepseek.com/v1`、`https://dashscope.aliyuncs.com/compatible-mode/v1` |
| 模型名称 | 例如 `deepseek-chat`、`qwen-plus` |

保存后回到应用，把 LLM 节点的模型选成刚加的这个。DSL 里默认写的是 `gpt-4o-mini`，
**导入后必须按自己的供应商改一次**，否则该节点会报"模型不可用"。

### 6. 访问入口

Dify → 工作室 → 忘川客栈 → 预览/运行；或「访问 API」用 `/v1/chat-messages` 接入。

## 五、已知限制

- 记忆检索走 PowerContext 的 FTS（默认 `mode: auto`，未配置 Embedding 时自动退化为全文检索），
  中文分词对极短句（如"怕水"）效果一般；如需更强召回，可给 PowerContext 配置 Embedding 服务。
- 记忆只增不减：作品没有做"账本最多 N 条"的取舍玩法，需要清理时用
  `POST /v1/memory/entries/list` 找到 citation 后 `POST /v1/memory/entries/retire`。
- 若 PowerContext 不可用，`http_search` 节点配置了默认值 `{"hits":[]}`，应用会退化为"账本空白"的失忆表现，
  不会崩；`http_remember` 失败则会直接报错，便于发现写入问题。
- 本作品不依赖知识库；Dify 的 seekdb 只用于满足其向量库依赖。
