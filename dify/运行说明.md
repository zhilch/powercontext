# 忘川客栈 · 运行说明

> 作品：**忘川客栈**——一个"记忆是一种资源"的互动剧情小游戏。
> 技术：**Dify**（流程编排）+ **PowerContext**（记忆账本）。
> 提交材料：`忘川客栈.yml`（DSL）、本说明、《验证样例.md》、《运行证据.md》、`powercontext/`、`scripts/`。

## 一、作品创意与玩法

客栈的规矩：客人喝下忘川水，睡一觉就会忘掉一切。世上只有掌柜**阿箬**那本《记忆账本》能留下东西。

- 你说 **「记住：我叫沈砚，怕水。」** → 阿箬提笔在账本上记一行，并把这句话复述给你。
- 你说别的（「掌柜的，又来了」）→ 阿箬**先翻账本**再开口：账本里有的（你的名字、你怕什么）她主动提起；账本里没有的，她真的不知道，会露出陌生的神色。
- **换一个新会话**（甚至关掉页面再打开）→ 阿箬依然记得沈砚和"怕水"。这不是会话记忆，是 PowerContext 里的长期记忆。
- 账本里查不到托付内容时，她会明确说"账上没这一笔"，**不编造**你上次说过什么。
- 记忆服务不可用时，她会表现为"账本空白"的失忆，而不是崩掉（见样例 4）。

为什么好玩：记忆不是外挂，而是**玩法本身**——你得决定留下什么、怎么留，才能让下一次见面的阿箬"认识"你。

## 二、技术分工

| 组成 | 在作品中的作用 | 对应位置 |
| --- | --- | --- |
| **Dify** | 全部流程编排：输入判断、HTTP 调用、账本整理、模型生成、回答输出 | `忘川客栈.yml` 的 10 个节点 |
| **PowerContext** | 记忆账本：写入玩家要求记住的事；每次开口前读取整个账本 | `http_remember`（`/v1/memory/remember`）、`http_search`（`/v1/memory/entries/list`） |

工作流结构：

```
玩家输入
  ├─ 含「记住」→ code_strip 取出去掉前缀的那句话
  │              → http_remember 写入 PowerContext → 记账回执
  └─ 其他      → http_search 翻账本（entries/list）
                 → code_ledger 整理成账本条目
                 → llm_npc 以阿箬身份开口（人设 + 账本）
                 → code_clean 去掉模型思考内容
                 → answer_npc 输出台词
```

两个 HTTP 节点直接调用 PowerContext 的公开 HTTP API，不依赖自定义插件；Dify 侧只用到官方的
HTTP Request、Code、LLM、Answer、IF/ELSE 节点。

> 题面要求"seekdb 或 PowerContext 至少一种"，本作品使用 **PowerContext**。
> 部署里 Dify 的向量库后端配成 seekdb（`VECTOR_STORE=seekdb`），只是为了让 Dify 在该网络下能起来，
> **本作品没有知识库**，seekdb 不承担作品的数据职责，也不作为技术结合的依据。

## 三、运行环境

| 项目 | 版本 / 要求 |
| --- | --- |
| Dify | 1.18.0（官方 `docker/docker-compose.yaml` 部署，DSL 版本 0.7.0） |
| 模型插件 | `langgenius/deepseek` **0.0.26**（DSL 已在 `dependencies` 中锁定该插件版本） |
| 模型 | `deepseek-flash`（DeepSeek-V4.1-Flash，1M 上下文） |
| PowerContext | 1.2.0（容器内 `pip install "powercontext[cli,server]==1.2.0"`） |
| 数据库 | Dify：PostgreSQL 15（容器内置）；PowerContext：SQLite（命名卷持久化） |
| 向量库 | seekdb（`oceanbase/seekdb:latest`，Dify 部署依赖） |
| 资源 | 内存 ≥ 8 GB、磁盘 ≥ 15 GB（镜像约 12 GB） |
| 系统 | Linux + Docker 24+ 与 Docker Compose v2（本文在 WSL2 Ubuntu 24.04 实测） |

## 四、部署步骤

### 1. 启动 Dify

```bash
curl -fsSL -o dify.tar.gz https://codeload.github.com/langgenius/dify/tar.gz/refs/tags/1.18.0
tar -xzf dify.tar.gz && cd dify-1.18.0/docker
cp .env.example .env
```

改 `.env`（每项的原因都写在注释里）：

```bash
# a) 向量库换成 seekdb：官方默认的 weaviate 镜像源 cr.weaviate.io 在部分网络不可达
sed -i 's/^VECTOR_STORE=.*/VECTOR_STORE=seekdb/' .env
cat >> .env <<'EOF'
OCEANBASE_VECTOR_HOST=seekdb
OCEANBASE_VECTOR_PORT=2881
OCEANBASE_VECTOR_USER=root
OCEANBASE_VECTOR_PASSWORD=difyai123456
OCEANBASE_VECTOR_DATABASE=dify
EOF

# b) 允许 HTTP 节点访问同网络的私有地址（PowerContext 容器）
#    先把 docker_default 的网段查出来，再填进去
SUBNET=$(docker network inspect docker_default --format '{{(index .IPAM.Config 0).Subnet}}' 2>/dev/null || echo 172.19.0.0/16)
echo "SSRF_PROXY_ALLOW_PRIVATE_IPS=$SUBNET" >> .env

# c) 如果模型/工具插件是从本地 .difypkg 安装（非市场），需要关掉签名校验
echo "FORCE_VERIFYING_SIGNATURE=false" >> .env

# d) INIT_PASSWORD 长度上限 30，超过会在首次初始化时返回 422
sed -i "s/^INIT_PASSWORD=.*/INIT_PASSWORD=$(openssl rand -hex 8)/" .env
```

> (b) 很关键：Dify 的 HTTP 节点走内置 Squid 代理，默认禁止访问私有网段，
> 不改这一项会报 `Access to 'http://powercontext:8000/...' was blocked by SSRF protection`。
> **改完后必须重建代理容器**：`docker compose up -d --force-recreate ssrf_proxy agent_ssrf_proxy`。

启动：

```bash
docker compose up -d
```

首次访问 <http://localhost>，用 `.env` 里的 `INIT_PASSWORD` 设置管理员账号。

### 2. 安装 DeepSeek 模型插件

**方式 A（推荐）**：设置 → 插件 → 探索市场 → 搜索 `deepseek` → 安装（版本 0.0.26）。

**方式 B（市场不可达时）**：从官方仓库 `langgenius/dify-official-plugins` 的 `models/deepseek`
目录打包成 `.difypkg`（zip，根目录含 `manifest.yaml`），然后：

```bash
# 上传 + 安装（需要控制台登录态与 X-CSRF-Token）
curl -X POST http://127.0.0.1/console/api/workspaces/current/plugin/upload/pkg \
  -F "pkg=@deepseek.difypkg"
curl -X POST http://127.0.0.1/console/api/workspaces/current/plugin/install/pkg \
  -H 'Content-Type: application/json' \
  -d '{"plugin_unique_identifiers":["langgenius/deepseek:0.0.26@<checksum>"]}'
```

安装完成后在 设置 → 模型供应商 → **深度求索** 里填入 DeepSeek 的 API Key，并添加模型 `deepseek-flash`。

### 3. 启动 PowerContext 记忆服务

```bash
cd dify/powercontext
docker compose -f docker-compose.powercontext.yaml up -d --build
curl -fsS http://127.0.0.1:8000/health/live   # 期望 200
```

该 compose 把 PowerContext 接入 Dify 的 `docker_default` 网络（容器名 `powercontext`），
因此工作流里用 `http://powercontext:8000` 访问；数据落在命名卷 `powercontext-data`。
服务以"无鉴权 + 允许非 loopback"的本地演示配置启动（见 `Dockerfile` 里的 `POWERCONTEXT_SERVER_*`），
仅适用于本机演示，不要直接暴露到公网。

### 4. 初始化记忆账本

```bash
cd dify/scripts
bash init_powercontext.sh
# 最后一行：初始化完成。WANGCHUAN_SCOPE_ID=<scope_id>
```

脚本会建 scope（幂等键 `wangchuan-inn-main`）并写入 3 条开局设定（客栈规矩、阿箬人设、失忆规则）。

### 5. 导入 DSL

1. Dify → 工作室 → 导入 DSL 文件 → 选择 `dify/忘川客栈.yml`。
2. 打开应用 → **环境变量**：
   - `WANGCHUAN_SCOPE_ID` 改成第 4 步输出的 `scope_id`；
   - `POWERCONTEXT_BASE_URL` 默认 `http://powercontext:8000`，若 PowerContext 不在同一网络改成实际地址。
3. 打开 LLM 节点「阿箬开口」，模型确认是 **deepseek / deepseek-flash**（若你的供应商 id 不同，选你自己的 DeepSeek 模型即可）。
4. 发布应用。

### 6. 访问入口

Dify → 工作室 → 忘川客栈 → 预览/运行；或在应用「访问 API」里创建 API Key，用 `/v1/chat-messages` 接入。

## 五、关键设计说明

| 设计 | 原因 |
| --- | --- |
| 账本用 `entries/list` 而不是 `search` | 阿箬是"翻整本账"，玩家说"我又来了"这类话不含关键词，`search` 会召回不到。整本账才是这个玩法的语义 |
| 记账分支用 `contains "记住"` 判断 | 一个 IF/ELSE 就能把"写入"和"读取"分开，玩家侧只需一个前缀，规则直观 |
| `code_clean` 去掉 `<think>` | DeepSeek V4 系列默认带思考内容，不去掉会混进台词；这个节点同时清掉 `<!--dify-deepseek-reasoning-->` 标记 |
| `http_search` 配 `default-value: {"entries":[]}` | 记忆服务挂掉时退化为"账本空白"的失忆演出，而不是整个应用报错 |
| 两个 HTTP 节点都带重试（2 次，指数退避） | PowerContext 重启/短暂抖动时自动恢复 |

## 六、已知限制

- 记忆只增不减：作品没有做"账本最多 N 条"的取舍玩法；需要清理时用
  `POST /v1/memory/entries/list` 拿到 citation 后 `POST /v1/memory/entries/retire`。
- 检索走 PowerContext 的 FTS（默认 `mode: auto`，未配置 Embedding 时自动退化为全文检索）；
  本作品主要用整本账读取，检索只作为核对手段。
- 演示实例关闭了插件签名校验（`FORCE_VERIFYING_SIGNATURE=false`），仅因为插件是本地打包安装；
  从市场安装的实例不需要这一项。
- 本作品不依赖知识库；Dify 的 seekdb 只用于满足其向量库依赖。
