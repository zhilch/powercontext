# 忘川客栈 · 验证样例

> 前置：按《运行说明.md》完成 Dify 与 PowerContext 部署、导入了 DSL、填好 `WANGCHUAN_SCOPE_ID`、绑定了模型。
> 每个样例都可以独立执行；样例 2 依赖样例 1 写入的记忆。

## 样例 1：把一件事写进账本（记忆写入）

**初始状态**：全新 scope（刚跑完 `init_powercontext.sh`，账本里只有 3 条开局设定）。

**输入**

```text
记住：我叫沈砚，怕水。
```

**操作步骤**：在 Dify 应用对话窗口发送上面这句话。

**预期表现**

- 命中的是工作流的 **true 分支**（含"记住"）：`code_strip` 去掉前缀 → `http_remember` 写入 → 记账回执。
- 回答形如：
  > （阿箬提笔，在账本上添了一行）「记下了：我叫沈砚，怕水。」*她把笔搁回去，抬眼看你。*「明日你若还记得，便是你自己记住的；若忘了，我替你记着。」
- **核对记录**：PowerContext 里出现一条新记忆：

```bash
curl -sS -X POST http://127.0.0.1:8000/v1/memory/search \
  -H 'Content-Type: application/json' \
  -d '{"scope_id":"<你的 scope_id>","query":"沈砚 水","limit":5,"mode":"auto"}' | python3 -m json.tool
```

应能在 `hits[].text` 里看到 `我叫沈砚，怕水。`（`matched_by` 至少包含 `fts`）。

## 样例 2：换个会话，她还记得（跨会话复用）

**初始状态**：样例 1 已执行。

**输入**（**新建一个会话**再发，模拟"隔天再来"）

```text
掌柜的，我又来了。
```

**操作步骤**：点"新对话"，然后发送这句话。

**预期表现**

- 走 **false 分支**：`http_search` 用"掌柜的，我又来了"检索账本 → `code_ledger` 整理 → LLM 带着账本开口。
- 回答应**主动提到**沈砚 / 怕水，例如：
  > *阿箬从账本上抬起眼，看了你一会儿。*「沈砚。」她把灯往你这边移了移。「上回你说怕水——今夜外头正是雨天，这碗姜汤你先喝。」……
- 反例：如果回答仍然像第一次见面（完全没提沈砚），说明 `WANGCHUAN_SCOPE_ID` 填错或检索失败，请检查环境变量与 `/v1/memory/search` 是否 200。

## 样例 3：账本没写的事，她真的不记得（不自造记忆）

**初始状态**：样例 1 已执行（账本里只有"沈砚、怕水"）。

**输入**

```text
我上次托你办的事，办了吗？
```

**预期表现**

- 账本里没有"托付"相关内容 → 阿箬应表现出**不记得**，且**不能编造**具体委托内容。例如：
  > *阿箬翻了两页账本，眉头微皱。*「托我办事？」她把账本合上，「客官，账本上没这一笔。你若真托过，怕是连我也忘了——不如再说一遍。」
- 判定要点：回答里**不出现**任何账本中没有的具体事件、人名或承诺。

## 样例 4：PowerContext 不可用时的降级（异常处理）

**操作步骤**

```bash
docker stop powercontext
```

然后在新会话发送：

```text
掌柜的，你还记得我吗？
```

**预期表现**

- `http_search` 连接失败 → 节点启用 `default-value`，返回 `{"hits":[]}` →
  `code_ledger` 得到空账本 → 阿箬按"账本空白"演初次见面，**应用不报错、不崩溃**。
- 恢复：

```bash
docker start powercontext
```

再次询问，阿箬应重新记起沈砚。
